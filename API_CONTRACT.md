# Contrato interno de la aplicación

## Estructura y convenciones
Aplicación Node 20+ con Express en JavaScript ESM; frontend React+Vite/TypeScript. MySQL con `mysql2/promise`. Los agentes trabajan exclusivamente en las carpetas indicadas; no sobreescribir archivos de otros. El punto de entrada será `server/index.js` y lo escribe el integrador. Env vars de Plesk: DATABASE_URL, SESSION_SECRET, APP_ORIGIN, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, SMTP_PASSWORD, BOOTSTRAP_ADMIN_EMAIL, BOOTSTRAP_ADMIN_PASSWORD, PORT; no .env. Zona horaria Europe/Madrid. Sumas en céntimos enteros. No inventar datos ni claves.

Todas las APIs responden JSON: éxito `{ok:true,...}`; fallo `{ok:false,error:'mensaje legible'}` con código HTTP adecuado. El frontend hace `fetch` relativo con credentials same-origin, `Content-Type: application/json`, y tratar 401/403. Los IDs son enteros. Servidor debe restringir datos por familia y rol. Público: `/`, `/asociacion`, `/contacto`, `/alta`, `/acceso`; privado `/socios`, `/socios/familia`, `/socios/cuotas`, `/socios/eventos`, `/admin`, `/admin/socios`, `/admin/cuotas`, `/admin/eventos`, `/admin/configuracion`. Servir SPA sin ocultar APIs; HTML público tiene metadatos y textos indexables.

## Tablas
Esquema canónico y nombres exactos: `database/schema.sql` (se construye simultáneamente); agentes deben leerlo antes de codificar. No cambiar esquema sin coordinación; reportar campos faltantes. `db` será un pool de mysql2/promise, importado desde `server/lib/db.js` por los módulos de rutas. Un objeto de sesión en `req.session.userId`, `req.session.role`, `req.session.familyId`. Exportar `requireUser`, `requireAdmin` de `server/lib/auth.js`. Cada enrutador exporta `default router`. El integrador montará las rutas en /api/... y webhook raw antes del parser JSON.

## Auth y datos generales (responsabilidad A)
- POST `/api/auth/register` `{name,email,password,phone,address,members:[{name,relationship}]}` => crear familia y usuario miembro; familia pendiente de aprobación, usuario puede acceder a sus datos pero no comprar hasta que admin active; registrar consentimiento explícito `privacyAccepted`. 2026 exento y primer cargo 2027 solo desde 1/1/2027; no registrar 2025 pagado para personas nuevas. No cobrar en año exento.
- POST `/api/auth/login` `{email,password}`; POST `/api/auth/logout`; GET `/api/auth/me` => `{user:{id,name,email,role,familyId},family}` o `{user:null}`. Reset de contraseña por SMTP seguro cuando esté configurado si es viable.
- GET `/api/public/config` => `{settings,upcomingEvents}`; POST `/api/contact` `{name,email,message}` => persistir y notificar a uno o dos destinatarios configurados. Si SMTP no está configurado, informar que no se envió y no reportar falso éxito.
- GET `/api/member/summary` => `{family,members,charges,payments}`. PUT `/api/member/profile` `{name,email,phone,address}`. POST `/api/member/members` `{name,relationship}`; DELETE `/api/member/members/:id` con autorización y límites.
- GET `/api/admin/overview` => `{counts}`; GET `/api/admin/families` => `{families}`; PATCH `/api/admin/families/:id` `{status,address,phone}`; GET `/api/admin/charges` => `{charges}`. POST `/api/admin/charges/generate` `{year}` respeta 2026 exento, 2027+ desde 1 enero y crea una por familia de forma idempotente; POST `/api/admin/charges/extra` `{familyId,description,amountCents,dueDate}`; POST `/api/admin/charges/:id/mark-paid` `{reference}`. GET/PUT `/api/admin/settings` => settings editables, SMTP_PASSWORD solo env; exportación GET `/api/admin/export/:type` para families/members/charges/payments (CSV).
- `server/lib/mail.js` crea correo y utilidades; configuración SMTP no sensible en tabla settings, password desde proceso. Usa nodemailer.
- Autenticación real: express-session persistida en MySQL, contraseñas bcrypt, cookies HttpOnly/Secure/SameSite adaptadas para iframe HTTPS y localhost; origin checks/CSRF para POST/PUT/PATCH/DELETE, límite intentos login; validación estricta, no privilegios de prueba.

## Eventos, Stripe (responsabilidad B)
- GET `/api/member/events` => `{events}` con `rsvp`, `memberLimit`, `memberBooked`; POST `/api/member/events/:id/rsvp` `{attending:true|false}`; POST `/api/member/events/:id/checkout` `{memberQty,guestQty}` => `{url}` creado por Stripe, o error inequívoco de falta de configuración; nunca registrar pagado por el retorno del usuario. Requiere familia activa; validar precios, sumas, límites y estado en servidor. Límite acumulativo de entradas familiares pagadas y reservas activas. Bloquear fila de familia y evento y reservar dentro de transacción. Invitados sin límite propio salvo aforo. Las reservas caducadas dejan de contar; pagos tardíos requieren manejo seguro para evitar sobreventa.
- GET `/api/admin/events` => `{events}`; POST `/api/admin/events` `{title,description,startsAt,location,ticketsEnabled,memberPriceCents,guestPriceCents,priceConfirmed,published}`; PUT `/api/admin/events/:id`; GET `/api/admin/events/:id/attendees` => `{rsvps,orders}`.
- POST `/api/member/charges/:id/checkout` => `{url}`. POST `/api/member/card/setup` => `{url}` al flujo Stripe que permita configurar cobro recurrente, con consentimiento. Nunca inventar pago automático si no se implementa completo.
- POST `/api/stripe/webhook` recibe raw bytes, verifica STRIPE_WEBHOOK_SECRET, persiste IDs de eventos, usa transacciones para idempotencia; registrar pagos efectivos de evento/cuota/subscription con ID Stripe, no datos de tarjeta. Eventos fuera de orden, reintentos, deduplicación por payment intent/factura, no contabilidad de exenciones. Registrar vía endpoint propio del VPS.
- `APP_ORIGIN` explícito como https://vegadesanjuan.es para redirecciones, no derivado de Host. Si Stripe falta, mostrar botón deshabilitado/error y no simular cobros. El precio provisional del Cartero Real no habilita compra hasta `price_confirmed` de admin.
- Archivos propios `server/routes/events.js`, `server/routes/stripe.js`, `server/lib/stripe.js`. Exportar routers y raw webhook handler. Manejo de cuotas anuales recurrentes con `invoice.paid` y `invoice.payment_failed` (en Stripe VPS configurar esos eventos); no vincular un pago de alta de tarjeta al año exento. Reportar limitaciones reales.

## Frontend (responsabilidad C)
Archivos exclusivos `client/src/**`, `client/index.html`, `client/vite.config.ts`. Interfaz completa y usable de las rutas arriba, usando solo las APIs pactadas, con estado de carga/error/éxito real, sin datos inventados ni acciones simuladas. Si datos o pagos están pendientes, indicarlo explícitamente. Web pública moderna, cálida, marca logo `/assets/logo-original.png`, referencias al usuario y a San Juan de Aznalfarache, 20 € al año por familia, objetivos y urbanizaciones reales; solicitar consentimiento en alta. Diseño responsive y accesible en español. Gestión de cuenta, familiares, cuotas, elección manual/tarjeta, eventos/RSVP/checkout; administración gestión de familias, cargos, eventos, asistentes y SMTP. Para las llamadas fetch, URLs de API relativas. Mostrar versión `Versión v1.0.0. [fecha y hora de compilación]` discretamente en configuración o pie, lectura de `__BUILD_INFO__` si disponible. Logotipo sin recorte destructivo; recurso original tiene margen transparente.
